## Implemented in this application

- A persistent director schedules 1–3 actual concurrent, focused shot sessions. Shared sets have a seed dependency. Each session has separate abort handles, tool scope, usage, review files and saved history. Stops/failures settle peers before returning; accepted shots survive restart.
- A seven-role cast table changes body, matte/glossy/glow finish and color across existing shots without regenerating geometry. Existing semantic roles remain compatible. The Update engine action migrates older mannequin roles and preserves their colors in a reversible project commit.
- Actual user-imported Mixamo skins, with male/female slots reused for new projects in the workspace, project folder import and per-role model selection. The source mesh and skeleton remain intact. Standard humanoid bone directions are retargeted to the action controller, including finger grips and attached props. Two original procedural bodies remain an explicit fallback. Fifteen built-in actions include phone, carrying, pointing, sitting down and standing up.
- Self-contained FBX/GLB character import up to 150 MB per file, skeleton-name reporting, embedded animation playback and fitting to the requested actor height. Folder imports recognize X Bot / Y Bot for the female / male slots and report each failure. FBX/GLB humanoid motion import maps supported limb names to Mixamo and procedural bodies, with named project assets and deterministic seeking. Arbitrary custom character overrides retain their own embedded clips. Missing body imports fail explicitly before rendering/export and do not waste AI repair attempts.
- Ten named camera moves compile to actual deterministic camera/target motion. Existing shots can receive a move directly, with a History checkpoint.
- Scene failures during export trigger a scoped repair, programmatic and independent image review, then a complete export restart. Bounded to one repair per shot and three per export; switchable off. Encoder/system failures are reported directly. Rejected repairs restore the original scene.
- Investigation no longer instructs the builder to invent crime imagery for unrelated topics. Shared production and licensed model acquisition now apply to both reconstruction looks.

## Limits and evidence

The reference's complete 131-motion library is not reproduced: this build contains 15 original actions plus user-imported motion. Asset scouting/download happens in production preflight; there are no separate simultaneous AI model-scout and prop-designer sessions. Scene builders and their reviewers run concurrently with set dependencies. Standard Mixamo humanoids are supported; universal retargeting of arbitrary custom rigs and facial animation are not certified. External textures must be embedded in character files. The user's local character folder is imported on request; no Mixamo meshes or downloaded review media are included in the app package or repository.

Actual renderer/API/UI tests cover both bodies and all built-in action transforms, grounded sitting transitions, role changes without rewriting scene geometry, named camera determinism, a real public Three.js FBX motion and character conversion, native animation playback, and export recovery into a real MP4. These checks do not establish full documentary quality or the reference's performance claims. Test media and workspaces are isolated and ignored by Git.
